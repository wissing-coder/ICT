# 听雨轩 · 公开试玩候选版交接

## 运行与发布
本地需要 Node.js 24。运行 `node game/server.mjs`，打开 http://127.0.0.1:8787 。`node --test game/game.test.mjs` 在临时目录独立运行测试。

公网部署需要团队提供已指向主机的域名，开放 80 和 443，并安装 Docker Compose。在仓库根目录设置 GAME_DOMAIN 后运行 `docker compose up -d --build`。访问域名下的 /healthz，随后用另一网络开房、进房、刷新。rooms 卷保存对局，certificates 卷保存证书。发布前记录当前镜像 ID 及源代码提交。

备份时执行 `docker compose cp game:/state/rooms.json ./rooms-backup.json`。首次开局后才有该文件。服务端以临时文件和重命名更新快照。备份含完整对局，请在私有存储定时执行并限制访问。回滚时先停 game，保留当前快照，再将相应版本的备份恢复至 rooms 卷，确保 node 用户可读写，使用对应代码版本重建并验证原浏览器可以重连。

## 产品与技术说明
三名当事人各自掌握一部分事实。玩家从证物发起具名追问，公开回答回到证物详情。日记只记录死者生前所知。指认后按玩家亲自引用的证物解释推断边界。独自进入时两个 AI 席位使用相同的搜证与投票规则。Node.js 服务端控制阶段、私卡和投票；手机浏览器轮询房间状态。模型超时可以用本地答复继续。

## 三分钟现场演示分镜
- 0:00–0:35 选苏明玉，读出「我听到翻纸，没看见屋里的人」，从角色的问题进入现场。
- 0:35–1:20 展开遗嘱草稿，点引用追问，将问题改成「你当时知道这只是草稿吗？」点名队友，再返回证物找对应答复。
- 1:20–2:05 切换到预先进入调查的房间。取得日记，先读落款和原文，核对它对医生的说法究竟支持到哪一步。
- 2:05–2:50 展示预先完成的对局。对照自己引用的证物、实际票数和角色秘密，指出动机还缺哪些独立证据。
- 2:50–3:00 展示真实盲测结果。现场录像剪辑时注明跨阶段跳转和提前准备的房间。

## 盲测记录单
每局使用独立组号，记录版本、设备、三个角色、开局时间、第一次自主追问时间、结算时间、卡点、是否获得观察者提示。分别记录每人是否参与对质，以及其陈述的选择、依据、改变判断的发言。观察者只在第一轮结束后复盘。每轮三组新人。第二轮三组独立完成、至少两组在 15–20 分钟结算、至少七人说清有效证据关系才达到发布门槛。

## 已取得的测试结果
14 项 Node 集成测试通过。20 个并行单人双 AI 房间在本机批量开局用时 23 毫秒，零失败。测试另验证跨房回复被拒、证物引用继承，以及用备份文件启动后持原凭据找回讨论。此计时覆盖建房接口。另用 60 个独立客户端模拟真人席位，按角色匹配到 20 局，完成匹配与首次读取共 54 毫秒，含确认读本、搜证和点名回复的整段测试共 323 毫秒。此项为本机接口短时测试。真实手机、公网跨网络延迟及 18 人盲测需分别记录实测值。
