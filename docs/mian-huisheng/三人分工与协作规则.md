| 页面 | 负责人 | 理由 |

| 投票页（含倒计时） | **张宇恒** | 独立无耦合 |
| 结算页（真相揭晓 + AI复盘展示） | **张宇恒** | 只展示接口返回的文本 |
| 全局样式变量 / 配色 / 字体 | **张宇恒** | 统一视觉基调 |

**张宇恒 6 个页面 + 全局样式，陆豪 2 个页面。**

### 零美术怎么做出民国感

- **深底浅字**：背景 `#1a1614`（近黑褐），正文 `#e8dcc8`（米黄）
- **中文衬线体**：思源宋体（开源可商用）或 `font-family: serif`
- **纯色块头像**：`user.avatar_color` 字段就是为这个设计的，四个色块代替四张立绘
- **卡片 + 大留白 + 1px 细线边框**，圆角不要过大
- **所有主题色走 CSS 变量**，改一处全局生效

> 文字推理游戏的好处：**氛围靠字，不靠图。**

## 四、接口契约（🔴 Phase 0 必须定死）

> 学生团队散伙的第一原因不是能力不够，是**两个人对同一个接口的理解不一样**。
> 下面这些约定 Phase 0 就写进 README，之后不许单方面改。

### 4.1 统一响应体

```java
{
  "code": 0,          // 0=成功，非0=业务错误码
  "msg": "success",
  "data": { ... }     // 业务数据，失败时为 null
}
```

前端只判断 `code === 0`。

### 4.2 错误码表（只增不改）

| code | 含义 |
|---|---|
| 0 | 成功 |
| 1001 | 参数错误 |
| 1002 | 未登录 / token 失效 |
| 2001 | 房间不存在 |
| 2002 | 房间人数已满 |
| 2003 | 已在其他房间中 |
| 3001 | 当前阶段不允许此操作 |
| 3002 | 盘问配额已用完 |
| 3003 | 已投过票 |
| 4001 | AI 服务暂时不可用（降级提示） |

### 4.3 三个关键接口

**`GET /api/room/{id}/state`**（前端每2秒轮询 · 张越扬写，另两人用）

```json
{
  "roomId": 1,
  "status": 1,
  "phase": 3,
  "currentRound": 2,
  "phaseDeadline": "2026-12-05T21:35:00",
  "players": [
    {"seat":1, "userId":10, "nickname":"小明", "characterName":"苏明轩",
     "avatarColor":"#c0392b", "isConnected":true}
  ],
  "npcList": [{"npcId":1, "name":"陈伯（管家）", "type":1, "remainQuota":15}],
  "myClueCount": 3
}
```

**`POST /api/game/ask-npc`**（陆豪写核心，张越扬提供 Redis 支撑）

```json
// 请求
{ "npcId": 1, "question": "昨晚九点你在哪？" }

// 响应
{
  "code": 0,
  "data": {
    "npcName": "陈伯（管家）",
    "answer": "回您的话，二十一点十分老奴送完茶便回了仆人房……",
    "newClue": { "id": 9, "content": "陈伯的行踪：……" },
    "remainQuota": 12,
    "latencyMs": 2340
  }
}
```

**`GET /api/game/role`**（张越扬写，张宇恒用）

```json
{
  "characterName": "苏明轩",
  "publicInfo": "苏家长子，三十二岁……",
  "privateSecret": "你的丝厂亏空了三万大洋……",
  "playGuide": "你的目标是让票投给别人……",
  "avatarColor": "#c0392b"
}
```

> 🔴 **以上三个接口响应体里绝对不能出现**：`groundTruth`、`leakKeywords`、`isMurderer`、他人的 `privateSecret`。
> 用专门的 VO，**不要直接返回 Entity**。上线前张宇恒用 F12 逐个接口检查。

| 范围砍不砍 | 三人讨论，**张越扬有最终决定权** |

### 4.5 并行开发的关键：陆豪不等张越扬

Phase 2 陆豪做 ask-npc 时，张越扬的房间/状态机可能还没完全就绪。解决办法：

```
陆豪用假数据先调通：
  - roomId、userId 写死
  - 阶段校验先跳过
  - Redis 配额先用本地变量代替
等张越扬的接口就绪，替换成真实调用
```

**这就是接口契约要 Phase 0 定死的原因**——契约清楚了，两个人才能真正并行。

## 五、Git 协作规则

### 分支模型

```
main                        ← 只放能跑的版本，合并前必须本地跑通
  ├── feat/backend-core     ← 张越扬
  ├── feat/ai-npc           ← 陆豪
  ├── feat/frontend-ask     ← 陆豪（盘问页 + 讨论区）
  ├── feat/frontend-pages   ← 张宇恒（6个页面）
  └── content/script        ← 张宇恒（剧本数据）
```

1. 每人在自己分支开发，完成后开 **Pull Request** 合并到 `main`
2. **合并前自己先跑一遍**
3. **不要直接往 main 推**
4. **互相 Code Review** —— 这是本项目最大的隐性收益之一，真实团队就这么工作
5. 每 2-3 天至少合并一次，攒久了冲突会要命

### Commit 规范

```
feat: 新增房间创建与加入接口
fix: 修复投票时未校验房间阶段的问题
docs: 补充 README 的本地启动步骤
refactor: 抽取 Prompt 组装逻辑为独立 Service
test: 补充泄密拦截的单元测试
content: 修改陈伯的人设文本，减少主动展开
chore: 升级 Spring Boot 到 3.2.1
```

> **面试官翻你仓库，第一眼看的就是 commit 历史。** 一条 "update" 到底的仓库和规范化历史的仓库，印象分差很多。

### .gitignore（必须有）

```
target/
node_modules/
dist/
.env
application-local.yml
*.log
.idea/
.vscode/
.DS_Store
```

> 🔴 **`.env` 和 `application-local.yml` 必须排除**——里面有数据库密码和大模型 API Key。
> 提交过一次就洗不掉（Git 历史里永远在），到时候得重置整个仓库。
> **第一次 commit 之前就要配好。**

### 配置怎么传

```
本地开发：application-local.yml（不提交，每人自己配）
云端部署：服务器上的 .env 文件（权限 600，不进 Git）
代码里：  只读环境变量，如 System.getenv("AI_API_KEY")
仓库里：  放 application-local.yml.example（占位值）
```

## 七、风险与应对

| 风险 | 概率 | 应对 |
|---|---|---|
| **AI 表现不稳（出戏/编造/泄露）** | **高** | Phase 0 就手工试 30 轮；有兜底回复池；实在不行降级为只做死者日记问答 |
| **期末考试挤占时间** | **高** | 已预留 1/4-1/20 缓冲期，只修 bug 不加功能 |
| **寒假有人回家/实习/旅游** | 中 | Phase 3 开始前先确认三人寒假可用时间，据此定升级项数量 |
| 剧本不好玩 | 中 | Phase 1 末内部试玩立刻发现；线索不够就加，凶手太好猜就加误导 |
| 某人中途退出 | 中 | 站会提前说；任务可在张越扬/张宇恒之间互换（接口契约清晰才换得动） |
| 范围膨胀 | **高** | 第六节"默认不做"规则；每周五检查进度 |
| 云服务器花钱超预期 | 低 | Phase 3 才买，先查学生优惠；内网穿透可以顶很久 |
| 三人意见冲突 | 低 | 张越扬有最终决定权，记进 DECISIONS.md，不反复讨论 |

### 保命降级方案（进度落后时按顺序砍）

```
第1刀：砍掉"第二轮讨论"阶段（讨论 → 盘问 → 投票）
第2刀：砍掉结算 AI 复盘（改固定文案）
第3刀：砍掉多人联机，改成单人 + AI（一个人盘问所有 NPC）
第4刀：砍掉 AI NPC 陈伯，只保留死者日记问答
────── 以上都砍完还能玩，就是"单机版 AI 推理游戏" ──────
绝不能砍：AI 盘问功能本身（砍了这个项目就失去核心价值）
```

### 最小可交付版本（如果只能做一件事）

```
单人模式：玩家一个人，盘问 AI 陈伯和死者日记，收集线索，最后指认凶手
```

这个版本 **2-3 周就能做完**，包含了项目最核心的技术（Prompt 工程 + 防泄密 + 线索触发 + 大模型集成），简历上照样能写。

**如果 Phase 1 结束发现进度严重落后，直接切到这个版本，别硬撑多人联机。**

## 十一、一句实在话

不参赛之后，**最大的风险不是技术，是失去死线之后不了了之。**

学生项目烂尾的原因几乎从来不是"太难"，而是"没人催、慢慢就不做了"。所以三件事必须做到：

1. **每日站会不能断**（期末可降频，但不能停）——这是唯一的强制节奏
2. **每周五检查进度**，落后就按第七节砍，别硬扛
3. **Phase 2 末（1月3日）必须达成可玩最小版本**——这是心理上的"完成线"，跨过去之后项目就不会烂尾了

记住你们的真实目标：

> **不是做完一个游戏，是做出一段能在面试里聊 20 分钟、经得起追问的工程经历。**

所以宁可功能少一点，也要每个功能都能讲清楚"为什么这么设计、遇到什么问题、怎么解决的"。
