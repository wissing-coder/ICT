## ① `play_guide`：已解决，仅存档

**现状**：`character` 表有 `play_guide TEXT`（技术方案第四节），`/api/game/role` 也返回 `playGuide`，但剧本第七节的 `INSERT` 没有该字段——四段「玩法指引」被塞在 `private_secret` 尾部，以「【玩法指引】」为分隔符。后果是角色卡页设计好的「秘密 / 玩法指引」分区没有数据可渲染。

**处理**：已生成 `sql/init_data_character.sql`，把四段玩法指引切到独立字段。两种落地方式（整段替换 / 4 条 `UPDATE`）与 3 条校验 SQL 都在文件里，期望值 `4 / 0 / 0`。

**连带约定**：Prompt 组装只用 `private_secret`，**不要带 `play_guide`**。玩法指引是写给玩家的攻略（「引导怀疑林医生」「反驳我手冷」），喂给模型它会照着演。

## ② 房间页要「准备」，但后端没有这个能力

**现状**：

```
分工表 Phase 1：张宇恒 → 房间页（座位 / 准备 / 开始）
接口清单：      POST /api/room/{id}/join、/leave、/start      ← 没有 /ready
room_player：   seat、is_alive、is_connected、last_seen_at     ← 没有 is_ready
```

**方案对比**：

| | 方案 A（加能力） | 方案 B（砍功能） |
|---|---|---|
| 表结构 | `room_player` 加 `is_ready TINYINT NOT NULL DEFAULT 0` | 不改 |
| 接口 | 新增 `POST /api/room/{id}/ready`（toggle） | 不改 |
| 状态同步 | `is_ready` 要进 `/state` 的 `players[]` | 不改 |
| 前端 | 座位卡片加准备态；房主看谁没准备 | 删掉准备按钮，房主在人数达标时直接开始 |
| 后端工作量 | 约 30 分钟（一列 + 一个接口 + VO 加字段） | 0 |
| 代价 | 无 | 少一个「大家都到齐了」的仪式感；房主可能在人没到齐时误点开始 |

**建议：方案 A。** 理由：① 成本极低，一列一接口；② 3-4 人局里房主误点开始会直接毁掉一局（谁来当陈伯的分支没定就开了）；③ 「准备」是这类多人游戏的标准交互，面试时讲状态机也用得上。

**改完怎么验**：

```sql
DESC room_player;                      -- 应有 is_ready 列
```

1. `POST /api/room/{id}/ready` 返回 `code: 0`，重复调用能正确切换
2. `GET /api/room/{id}/state` 的 `players[]` 里每个元素带 `isReady`
3. 前端刷新页面后准备态不丢（说明落库或进了 Redis，不是内存变量）

## ③ `/api/room/{id}/state` 缺 `serverTime`，倒计时会跳

**现状**：返回体只有 `phaseDeadline`，没有服务端当前时间，前端只能拿本地 `Date.now()` 去减——手机时间不准或跨时区就会跳，甚至出现负数。

**方案对比**：

| | 方案 A（加字段） | 方案 B（读响应头） |
|---|---|---|
| 做法 | 响应体加 `serverTime` | 前端读 HTTP 响应头的 `Date` |
| 后端改动 | 一行（`LocalDateTime.now()`） | 0 |
| 精度 | 毫秒，可控 | 秒级，够用 |
| 风险 | 无 | 某些代理/网关会重写 `Date` 头 |

**建议：方案 A。** 一行代码，且以后做「服务器时间校准」也顺手。

**改完怎么验**：

1. 响应体含 `serverTime`，格式与 `phaseDeadline` 一致
2. 与服务端真实时间相差 < 1 秒
3. 前端倒计时 = `phaseDeadline - serverTime - 已流逝时间`，改手机系统时间后倒计时不跳

## ④ 建议（非缺口）：两个 2 秒轮询要不要合并

**现状**：技术方案把房间状态（`GET /api/room/{id}/state`）和讨论区（`GET /api/game/discuss?round=1`）设计成两个独立接口，各自 2 秒轮询。4 人局下每客户端每秒 2 次请求。

**建议**：合并成一个 tick——同一个定时器里并发拉两个接口；或讨论区只在「讨论阶段（phase 2 / 4）」才轮询，其它阶段停掉。

**为什么现在说**：Phase 0 定契约时提，成本是「约定一句」；Phase 3 演示卡了再优化，成本是「改前端 + 改后端 + 重测」。
